# H1：扩展安全格式与测试向量

本交接固定 A2 的保险库、完整备份、迁移和导入恢复语义，供 A3 移入共享 `security` 子路径。当前文件不是 npm 发布或许可 Desktop 复制另一份实现的依据。

## 格式与算法

### `shadekit-vault/v1`

- 每条记录字段仅为 `format`、`credentialId`、`iv`、`ciphertext`。
- DEK 为随机 256-bit；秘密记录使用 AES-256-GCM，每条记录独立随机 96-bit IV，128-bit authentication tag。
- AAD 固定为 `shadekit/vault/v1/account-switch/{credentialId}`，不绑定可编辑的 username/origin。
- 无感模式使用 IndexedDB 中不可提取 AES-KW KEK 包装 DEK；普通存储只保存 wrapped DEK 与密文。
- 主密码使用 PBKDF2-SHA-256，首版最低 600,000 次；KDF 名称、迭代数和 salt 随元数据保存。
- 修改主密码只在 Web Crypto 内 unwrap → wrap DEK，不重加密秘密记录；启用主密码后删除无感 KEK。
- 解锁 DEK 仅以不可提取 `CryptoKey` 存在 Background 模块内存。显式锁定、后台重启或浏览器重启后不承诺保持解锁。
- 认证、错误 KEK、AAD/IV/密文篡改统一为 `VAULT_AUTH_FAILED`；锁定和宿主不可用分别为 `VAULT_LOCKED`、`VAULT_UNAVAILABLE`，没有明文 DEK 降级。

### `shadekit-backup/v1`

- envelope 公开字段仅为 `format`、`backupId`、`kdf`、`dekWrap`、`wrappedDek`、`iv`、`ciphertext`。
- 独立备份密码经 PBKDF2-SHA-256 派生 KEK，使用 AES-KW 包装随机备份 DEK；整个递归规范化 key 后的 JSON payload 加密。
- payload AAD 为 `shadekit/backup/v1/{backupId}`。salt 16 字节、IV 12 字节、wrapped DEK 40 字节。
- portable payload 含白名单公共配置和本次导出所需秘密；不包含本机 KEK、本机 wrapped DEK、vault/meta/journal/recovery 记录。
- 导入先完成密码认证、schema/spec 与引用完整性校验，再进入写入阶段；秘密重新加密到本机 DEK。
- 错误密码、未知格式/KDF、backup id/AAD、salt、IV、wrapped DEK 或密文篡改统一为 `BACKUP_AUTH_FAILED`。
- 旧明文备份只有显式 `acceptPlaintextWarning` 后才能导入；文件文本不进入日志、UI 渲染或临时持久化。

## 固定向量

`fixtures/h1-security-vectors.json` 由独立 Node Web Crypto 计算生成，`tests/security-vectors.test.ts` 验证生产实现：

1. 固定 DEK、IV、credential ID 和 Unicode plaintext 的 vault 密文逐字节一致；更换 AAD credential ID 后失败。
2. 固定 backup ID、PBKDF2 salt/600,000 iterations、备份 DEK、IV 和规范化 payload 可重复生成同一 envelope；错误密码和 backup ID 篡改失败。
3. 固定迁移输入生成稳定账号、环境默认和全局默认引用，引用配置不包含秘密。

`tests/security-vault.test.ts` 与 `tests/security-backup.test.ts` 另外覆盖随机 IV/salt/backup ID、空/长/Unicode 秘密、AES-KW、rewrap，以及密文/IV/salt/wrapped DEK/KDF/format 篡改。

## 迁移与导入恢复向量

### 明文迁移

- 稳定 ID：账号 `account:{accountId}`；环境默认、全局默认、声明 secret var 与环境 secret var 使用各自命名空间。
- 每条 `putSecret` 后必须 `resolveSecret` 回读并比较原值；引用完整性在任何配置提交前验证。
- journal 阶段为 `started → prepared → committed`，只含无秘密配置。原配置用 `migration-recovery` AAD ID 加密保存。
- prepared 后崩溃：当前配置等于 prepared 时验证引用并幂等收尾；否则从加密 recovery 恢复后重试。恢复不发起真实登录。

### 完整备份导入

- journal 格式为 `shadekit-import-journal/v1`，prepared 阶段以 `import-recovery` AAD ID 加密保存受影响 key 的导入前快照。
- 写入、读回、秘密核对或孤立记录清理任一步失败，都按同一 journal 回滚 vault 与公共配置。
- 启动时先 `recoverInterruptedImport()`，再 `migratePlaintextSecrets()`；重复 recovery 后快照保持一致。
- fixture 的 `importRecovery` 固定 crash injection 与不变量；实际状态型崩溃注入见 `tests/encrypted-backup.test.ts`，启动顺序见 `tests/security-startup.test.ts`。

## 主密码续跑与重置

- pending intent 仅含 accountId、environmentId、原 tab ID、所属扩展和过期时间，不含秘密。
- 解锁后读取最新配置和真实 tab，再次校验账号绑定、顶层 sender 与实际 origin；一次性消费，取消、超时、跨 origin 导航或重放均不执行登录。
- 无已保存密码的账号走用户主动输入的一次性 `QUICK_LOGIN`，不自动保存。
- 重置删除秘密、引用、vault meta、迁移 recovery 与 import journal，保留公共配置；外部备份不受影响。

## KDF 本机基准

命令：`node scripts/benchmark-security-kdf.mjs`。

`evidence/h1-kdf-benchmark.json` 记录 2026-10-30 在 Node v20.20.2、darwin/arm64 上 600,000 次 PBKDF2-SHA-256 的三次实测：74.31、70.14、71.09 ms。该数据只用于本机量级检查，不是浏览器性能或跨平台承诺；不在测试中设置时间上限。
