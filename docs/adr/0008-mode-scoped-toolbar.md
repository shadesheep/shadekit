# ADR-0008: 模式作用域顶栏(Mode-scoped Toolbar)— 控件随模式变形/隐现

## 状态

已接受(2026-08-18)

## 背景

mock-data 工具页有两种模式:**批量生成**(字段列表 × 条数 → 数据集)与**快速取数**(点类型 → 候选值,点击即复制)。顶栏按「全局工具栏」设计,但实际全是批量模式的语义,快速模式下大面积失义:

- **条数输入框 + 预设**:只喂批量生成;快速取数的数量是 `quickCount`,藏在选项页——页面里存在两个「数量」概念、两个位置
- **「生成」主按钮永远调 `doGenerate()`**,而 ⌘⏎ 快捷键是模式感知的(快速 = 换一批)——快速模式下点按钮,toast 报「已生成 N 条」但右侧仍是候选值视图,结果不可见;按钮与快捷键语义互相矛盾
- **载入模板**:`applyTemplate` 强制切回批量模式,快速模式下选模板 = 无提示跳模式 + 覆盖不可见的字段列表
- **「清空」**:只清批量字段与结果,快速模式下候选值纹丝不动,名不副实
- **格式/表名等批量控件的变更**在快速模式下仍会触发 watcher,后台白跑一遍不可见的批量重新生成

根因:**顶栏的视觉是全局的,语义却是批量模式专属的**,两种模式共享一个顶栏但没有约定归属。

## 决策

**顶栏归属当前模式的作用域(Mode-scoped Toolbar):控件随 `leftMode` 变形或隐现,主按钮语义与快捷键始终一致。**

| 顶栏控件 | 批量生成模式 | 快速取数模式 |
|---|---|---|
| 主按钮 | 「生成 ⌘⏎」→ `doGenerate()` | 「换一批 ⌘⏎」→ `quickGenerate()`(无选中类型时禁用) |
| 条数输入框 | 绑 `count`(1–1000) | 变形为「候选」,绑 `quickCount`(1–20,与选项页同 key 同步) |
| 条数预设 1/10/50/100 | 显示 | 隐藏(候选上限 20,预设档无意义) |
| 输出格式 + SQL 表名 | 显示 | 隐藏 |
| 载入模板 + 重新应用 | 显示 | 隐藏(杜绝无提示切模式 + 覆盖不可见字段) |
| 清空 | 清字段与结果 | 清候选值,右侧回到类型选择空态 |

配套:

- **watcher 保险**:`scheduleGenerate` 仅在 `leftMode === 'batch'` 时触发,杜绝快速模式下任何残留路径引起不可见的批量重新生成
- **`leftMode` 持久化**到 `devtools-mock-data` config(与 `viewMode` 惯例一致),重开页面恢复上次模式;首屏批量生成也跳过快速模式(结果不可见,白跑)
- 「候选条数」由此从选项页专属偏好变为页内可改,选项页配置保留(两处同 key)

### 约定(供未来多模式工具)

1. 工具页若引入模式,顶栏控件必须声明归属:全局 / 模式 A / 模式 B;禁止「视觉全局、语义单模式」的控件存在
2. 变形优先于置灰:能被另一个模式复用位置的控件(条数 → 候选条数)变形,不能复用的隐藏,不用 disabled 占位
3. 主按钮与全局快捷键语义必须一致,都跟随当前模式

## 已否决的替代方案

- **方案 A:快速模式下禁用批量专属控件**:半个顶栏变灰仍占视觉位置,持续误导;disabled 控件不教用户理解模式边界
- **方案 C:批量专属控件下沉到左侧面板**:顶栏只剩品牌名被掏空,破坏与其他工具页「主操作收口在顶栏」的一致性(见 ADR-0001)
- **模板在快速模式保留但加 toast 提示**:模板是批量配置的入口型控件,留着等于一个会偷偷切模式的按钮;模式切换 segmented 就在手边,无需特洛伊木马
- **条数预设换成快速档(4/6/8/12)**:候选条数是「设一次基本不动」的偏好(因此本来就住选项页),为低频操作维持一排预设是视觉噪音,主次倒挂
- **不持久化 `leftMode`**:配置里已存 `quickCount`/`tablePreviewLimit` 等快速模式专属偏好,模式本身却不记得,设计不自洽;新用户无历史,默认仍是批量,不存在迷路问题

## 影响

- 仅 `entrypoints/mock-data/App.vue`(顶栏模板分叉 + `clearAll` 分叉 + watcher 保险 + 持久化)与 `tools/mock-data/lib/types.ts`(`LeftMode` 类型 + `MockDataConfig.leftMode`),无新组件、无新样式
- Config.vue 无需改动:`useToolConfig` 的浅合并会让 `leftMode` 随 ref 搭载保留(同 tableName 先例)
