# ADR 0001: 可用性优化方向 —— 入口收敛与效率优先

- **日期**: 2026-08-07
- **状态**: 已全部实施（D1–D7 均已落地，构建通过；待人工手测验收）
- **背景**: 对 DevTools 扩展做启发式可用性走查(heuristic evaluation),团队无现成痛点清单,走查结论逐条与负责人确认。

## 定位与总原则

1. **目标用户**: 开发/测试人员为主,按"可发布到商店"的标准打磨(首次体验、可发现性、错误提示对内部用户同样是净收益)。
2. **取舍原则**: **效率优先(power-user first) + 新手底线**。
   - 高频操作(账号切换、JSON 格式化)的点击数、自动化做到最优。
   - 新手底线 = 不 confusion、不破坏:看到任何 UI 知道是什么、能 1 步关掉;装完 5 分钟内不需问人即可上手。
   - 不为界面简洁牺牲功能入口可达性。

## 决策清单

### D1. 移除常驻 Dock(P0)

- 移除 content script 注入的常驻浮动 Dock(`#devtools-dock`,所有 http/https 页面)。
- **保留**: `Alt+Shift+A` 唤出的页面内账号切换面板(SwitcherPanel,功能本体,账号切换必须在页面上下文执行)、环境指示器(默认关闭)、toast 注入。
- 理由: Dock 的价值是可发现性,代价是全页面注入、遮挡页面、长期受宿主页 CSS 污染困扰(历史包袱见 git log)。popup + 快捷键足以覆盖入口需求。

### D2. 不新增快捷键、不扩充右键菜单

- 快捷键仅保留 `Alt+Shift+A`(账号切换 / 选中文本时快捷登录)。
- 右键菜单维持现有 3 项(选中文本 → JSON 格式化 / JSON 对比 / 快捷登录)。

### D3. 标签页复用(P1)

- 4 个标签页工具(JSON 格式化、JSON 对比、图片 Base64、代码美化)的 `allowMultiple` 默认值由 `true` 翻转为 `false`:同工具已有标签页则激活聚焦,没有才新开。
- 保留显式新开能力: popup 内中键点击 / 工具页内"新窗口"按钮。
- **硬约束**: 复用已有标签页时**绝不清空或覆盖其中已有内容**(因 D7 不做持久化,内容是用户唯一副本)。
- 代码现状: `background.ts` 的 `openToolTab` 已实现复用逻辑,仅需翻转默认值 + popup 加中键处理。

### D4. 轻量 onboarding(P1/P2)

- Popup 内账号切换项标注 `Alt+Shift+A`;JSON 工具项标注"可选中文字右键调用"。
- Popup 空状态(无启用工具时)提示"有 N 个工具被禁用,前往设置开启"。
- 首次安装时自动打开选项页,定位到账号切换的 GuideSection。
- **明确不做**: 多步引导、遮罩 walkthrough、欢迎页。

### D5. 账号配置降门槛(P2)

- 配置页增加"快速添加"文本框: 粘贴一行/多行 `用户名 密码 URL`,复用现有 `parse-text.ts` 解析成账号卡片,用户确认即可。
- 域名配置中的 `publicKey`、`apiBase` 等高级字段收进"高级设置"折叠区,默认值覆盖常见环境。

### D6. 失败反馈(P1)

- `Alt+Shift+A` 在受限页面(chrome://、商店页等)失败时,用 `chrome.notifications` 或页面 toast 提示"此页面不支持",不再静默 `catch {}`。
- 右键快捷登录解析失败维持回退开面板(可接受)。
- **明确不做**: 全面错误监控/上报。

### D7. 明确不做

- 内容持久化(关标签页即丢,"用完即走"是该工具的正确形态)。
- 新快捷键、扩充右键菜单(见 D2)。

## 已识别风险(本轮不决策)

- **账号密码明文存储**于 `chrome.storage.local`,任何扩展/本机用户可读。内部工具可接受;若上架商店,是审核与信任的硬伤。记档待后续决策。

## 实施顺序

1. **P0**: D1 移除 Dock(架构前提,其他改动建立在入口收敛之后)
2. **P1**: D3 标签页复用、D4 popup 标注与空状态提示、D6 失败反馈
3. **P2**: D4 首装打开选项页、D5 账号配置降门槛
